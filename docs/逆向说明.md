# 课表逆向说明

> 目标：学校的课表页面被关闭后，通过逆向「融合门户」前端接口，用本人登录态直接取回整学期课表。
> 本文记录 **入口分析 → 登录态获取 → 接口清单 → 数据字段 → 作息时间** 的完整过程。

---

## 1. 入口分析

| 入口 | 地址 | 说明 |
| --- | --- | --- |
| 企业微信课表 | `https://ydxy.gzist.edu.cn/ydxy_commonmodule/open/tips/error?title=1001&reason=...` | 企业微信里点「课表」跳转的地址，`tips/error` 是错误提示页（`title=1001` 即"功能已关闭/无权限"），本身没有数据 |
| 融合门户 | `https://portal.gzist.edu.cn/#/index4` | 统一门户首页，内含「学生课表」卡片，**真正的数据来源** |

结论：企业微信那个链接只是把用户导流到门户的一个失败提示页。真正可取数的是门户里的课表卡片，
它由前端异步调用后端 JSON 接口渲染，接口与「页面是否被关闭」无关——只要登录态还在就能调。

门户使用**联奕 ly-upp 融合门户**框架（前端资源里有 `app.*.js`、`cardComponents.*.js`、`uppcard` 等特征），
首页是一个"卡片（card）"网格，每张卡片对应一组后端接口。

## 2. 登录态获取

门户走统一身份认证（CAS）：

```
https://ids.gzist.edu.cn/lyuapServer/login?service=https://portal.gzist.edu.cn/shiro-cas
```

浏览器正常登录（账号密码 / 扫码 / 短信均可，含图形验证码）后，前端会把登录信息存进
`sessionStorage`，键名 **`userLogin`**，是一个 JSON 字符串，关键字段：

| 字段 | 含义 |
| --- | --- |
| `tokenId` | **JWT 访问令牌**，即接口请求头里的 `Authorization` |
| `accessToken` | 同上（不同版本命名不同，优先用 `tokenId`） |
| `userId` | 学号 |
| `userName` | 姓名 |
| `departmentName` | 班级（如 `xx xx xx班`） |
| `userType` | `student` |

**取 token 的最快方式**（浏览器已登录门户的情况下，F12 控制台）：

```js
JSON.parse(sessionStorage.getItem('userLogin')).tokenId
```

把它复制给抓取脚本即可：

```bash
node fetch/fetch.mjs --token "<粘贴 tokenId>"
```

> 注：token 有有效期，过期会返回 `meta.success=false`（鉴权失败），重新登录门户再取一次即可。

## 3. 接口清单

所有接口都在 `https://portal.gzist.edu.cn/` 下，公共请求头：

```
Authorization: <tokenId>
X-Requested-With: XMLHttpRequest
Accept: application/json, text/plain, */*
```

课表卡片对应路径前缀 `api/uppcard/kbsz/`，卡片实例 `cardId`
（可在门户课表卡片的网络请求里看到，脚本从环境变量 `GL_CARD_ID`（或 `--card-id` 参数）读取卡片 id，换成你自己的即可）。

### 3.1 学期列表

```
GET api/uppcard/kbsz/queryAllTerm?cardId=<CARD_ID>
```

返回 `data` 为学期数组，每项含 `XNXQ`（学年学期，如 `2026-2027-1`）。

### 3.2 某学期整周课表

```
GET api/uppcard/kbsz/queryAWeekSchedule?cardId=<CARD_ID>&results=&years=<学年学期>
```

返回 `data` 关键字段：

| 字段 | 含义 |
| --- | --- |
| `xn` / `xq` | 学年 / 学期（`1`/`2`） |
| `zs` | 周数（当前教学周） |
| `weekcount` | 学期总周数 |
| `swskjc` / `xwskjc` / `wsskjc` | 上午 / 下午 / 晚上各排几节（本校本学期为 4/4/4，共 12 节） |
| `resultsJsonArr` | **核心**：二维数组，`[行][列]` |

`resultsJsonArr` 是一个 **7 列（周一…周日）× N 行（第 1…N 节）** 的字符串网格。
每格是一个逗号拼接的字符串，格式：

```
课程名,教室,教学班信息...,教师
```

例如：

```
示例课程,某教学楼404,示例课程-xx xx xx班-理论,示例教师
```

空字符串 `""` 表示该时段没课。

> 网格里同一门课连排两节会**重复填两格**，脚本据此把相邻相同格合并成「课程块」，
> 记录 `startSection`~`endSection`，前端再按"起止节"渲染成跨行的卡片。

### 3.3 统一的返回外壳

所有接口统一返回：

```json
{ "meta": { "success": true, ... }, "data": ... }
```

脚本以 `meta.success === true` 判断成功。

## 4. 数据结构（本项目 `web/data.json`）

```jsonc
{
  "fetchedAt": "2026-10-21T08:56:42.093Z",
  "source": "portal.gzist.edu.cn / ly-upp kbsz",
  "cardId": "<你的 cardId>",
  "student": { "name": "张三", "dept": "xx xx xx班", "userId": "xxxxXXXXXXXX", "userType": "student" },
  "terms": ["2026-2027-1", "2026-2027-2"],
  "termsData": {
    "2026-2027-1": {
      "xn": "2026", "xq": "1", "zs": 8, "weekcount": 20,
      "swskjc": 4, "xwskjc": 4, "wsskjc": 4,
      "grid": [ /* 原始 7×12 字符串网格，保留可追溯 */ ],
      "blocks": [
        { "day": 0, "dayName": "周一", "startSection": 3, "endSection": 4,
          "name": "示例课程", "room": "某教学楼404",
          "teacher": "示例教师", "cls": "示例课程-xx xx xx班-理论" }
        // …
      ]
    },

  }
}
```

前端只用 `blocks`（已合并好的课程块），`grid` 保留原始数据以便核对。

## 5. 作息时间（上下课时间从哪来）

课表接口只给"第几节"，不给钟点，钟点要另外找。本项目采用的最终口径是
**每一节单独的上下课时间**，取自学校「课程表」App 课表页的实拍（学生端看到的就是这个）：

| 节次 | 上课 | 下课 | 节次 | 上课 | 下课 |
| --- | --- | --- | --- | --- | --- |
| 1 | 08:20 | 09:05 | 6 | 14:55 | 15:40 |
| 2 | 09:15 | 10:00 | 7 | 16:00 | 16:45 |
| 3 | 10:20 | 11:05 | 8 | 16:55 | 17:40 |
| 4 | 11:15 | 12:00 | 9 | 18:40 | 19:25 |
| 5 | 14:00 | 14:45 | 10 | 19:35 | 20:00 |
| — | — | — | 11 / 12 | 20:10–20:55 / 21:05–21:50（图中没有，按规律推测） |

前端用 `SECTION_TIME` 存这张表，`timeForBlock(b)` 输出「首节上课 → 末节下课」，
例如第 3–4 节 → `10:20–12:00`、第 9–10 节 → `18:40–20:00`；
`sectionDetail(b)` 再把逐节时间拼进课块的 `title` 提示，长按/悬停就能看到
「第3节 10:20–11:05 / 第4节 11:15–12:00」。这样即使课表接口某天给了奇数节次
（比如只占第 9 节），也能算出准确时间，不需要再按区间插值。

### 与教务处「错时错峰」通知的差异

`jwc.gzist.edu.cn` 上 2022 年的《关于继续实施师生错时错峰上下课的通知》把课程分两批：

- 第一批次：6 号、13 号教学楼的所有课程；第二批次：其他教学区（行政楼、图书馆、10 号楼等）；
- 两批的差别只在**第 3–4 节**（11:40 / 12:00 结束）和**第 7–8 节**（17:20 / 17:40 结束）；
  该通知里第 9–10 节写的是 19:00 – 20:30。

而课程表 App 实际显示的是**统一一套**时间：第 3–4 节一律到 12:00、第 7–8 节一律到 17:40、
第 9–10 节 18:40 – 20:00（比通知的 19:00 早 20 分钟）。本项目**以课程表 App 为准**，
因为它才是学生实际看到的排课口径。若学校恢复错峰，只需把 `SECTION_TIME` 里
第 3–4、7–8 节按批次拆成两张表，判断批次的办法仍可沿用
`/^\s*(6|13)\s*[-－—]/`（6/13 号楼属第一批次）。

## 6. 前端渲染要点

- 网格用 CSS Grid：`grid-template-columns: 节次列 + repeat(7, 1fr)`，行 `1fr` 均分撑满 `100dvh`。
- **时间只出现在左侧栏**：每格显示「节号 + 上课 + 下课」（如 `3` / `10:20` / `11:05`），
  完全对齐学校课表 App 的样子；课程卡片里不再出现时间，也不再出现「第 3-4 节」。
- 课程卡片只放「课程名（最多 3~4 行，超出省略）/ 教师 / 教室」，教室永远完整不截断。
- 每个课程块按 `day → 列`、`startSection ~ endSection → 跨行` 放置。
- **教室号完整**：`.room` 允许 `overflow-wrap:anywhere` 换行、**不做省略**；末尾的校区（`（白云）`）拆成
  `.zone` 小字并 `white-space:nowrap`，保证它整体换行而不是被拆成「（白 / 云）」。
- **上下课时间完整**：`.time` 不省略，窄列时在 `–`（`<wbr>`）处折成两行。
- **课程名可不完整**：`.name` 用 `-webkit-line-clamp:2`（矮块降为 1 行）截断。
- **横屏竖屏都一屏显示整周**：不强制转屏。竖屏时列只有 ~47px 宽、行很高，
  所以字号改成按**宽度**收敛（`min(19cqh, 24cqw)` 这类双约束），上课/下课时间竖排成两行，
  并隐藏「第几节」标签，把空间让给课程名（最多 4 行，仍允许截断）。

## 8. 本地服务 `server/server.mjs`（为什么需要它）

静态页面能"显示"课表，但要"经常是新的"，就绕不开三件事：**登录态会过期**、**token 有有效期**、
**跨域策略**。所以加了一个零依赖的本地 Node 服务，干四件事：

1. **托管 Cookie（Cookie Jar）**
   门户的登录态主要在 Cookie 里（部分还是 `HttpOnly`，浏览器 JS 读不到）。
   把浏览器 Cookie 一次性导入服务端（存 `data/auth.json`），之后由 Node 自己带 Cookie 请求，前端完全不碰凭据。

   ```bash
   # 浏览器 F12 → Network → 任一 api/uppcard 请求 → Copy as cURL
   node scripts/import-cookies.mjs clip.txt
   ```

2. **定时同步**：默认每 `SYNC_MIN=15` 分钟拉一次 `queryAllTerm + queryAWeekSchedule`，
   结果原子写到 `web/data.json` 与 `web/data.js`。

3. **静默续期**：每 `KEEPALIVE_MIN=5` 分钟访问一次门户，配合 CAS 的 `CASTGC` 走
   `CASTGC → ST → service ticket` 自动换新会话，只要 `CASTGC` 没过期就能长期免登录。

4. **给前端 `/api/*`**（同源，无 CORS 烦恼）：

   | 方法 | 路径 | 说明 |
   | --- | --- | --- |
   | GET | `/api/schedule` | 最新课表数据 + 同步状态（`fetchedAt`、`needLogin`…） |
   | POST | `/api/sync` | 立即同步一次（前端「更新」按钮用的就是它） |
   | GET | `/api/state` | 仅状态：`status / lastSyncAt / lastError / needLogin / hasCookies` |
   | POST | `/api/auth/cookies` | 导入 Cookie（`{cookie}` 原始串，或 `{cookies:[CDP 格式]}`） |
   | POST | `/api/auth/logout` | 退出登录 / 换账号：清空 Cookie，`{wipe:true}` 连课表数据一起清 |

   启动：`node server/server.mjs`（或 `npm start`），默认 `http://127.0.0.1:8787`。
   环境变量：`GL_PORT`（端口）、`SYNC_MIN`、`KEEPALIVE_MIN`。

> 为什么不直接在浏览器里调门户接口？因为门户接口要带 `Authorization` + `csrf` 头，且
> `Access-Control-Allow-Origin` 不含本页面源，浏览器直接 `fetch` 会被 CORS 拦住；
> 服务端中转既解决 CORS，也把"登录态"和"页面"解耦。

## 9. 前端数据流（打开即见、后台更新、断网可用）

```
localStorage 缓存 ──立即渲染──▶ 界面
       ▲                          │
       │                          ▼
   /api/schedule ◀── 每 45s / 页面可见时 ── 拉最新
       │
   /api/sync ◀── 用户点「更新」── 立即同步
```

- **缓存优先**：`localStorage['kb.cache.v2']` 存上次成功的数据，**冷启动立刻有画面**，不白屏等待。
- **后台同步**：随后请求 `/api/schedule`，`fetchedAt` 变了才重渲染，避免闪烁。
- **状态可见**：顶栏胶囊显示 `已同步 · 10-21 17:09` / `缓存 · … · 同步中…` / `离线 · 缓存 …` /
  `登录失效 · 点此处理`（点开有导入 Cookie 的步骤说明）；长按/悬停胶囊可看精确更新时间。
- **断网/未启动服务**：自动降级为「离线 · 缓存」，课表照常显示；`file://` 双击打开时退回 `data.js` 内置数据。
- **响应式**：课程块用 CSS **容器查询**（`container-type:size` + `cqh`）让字号随课块自身高度缩放，
  568×320 这类极窄横屏也不会文字重叠。

## 10. 登录态过期与换账号

### 10.1 Cookie 过期时会发生什么

服务端每次请求都带 Cookie 去打门户。一旦登录态失效，会出现以下链条：

| 阶段 | 服务端行为 | 前端表现 |
| --- | --- | --- |
| 接口被重定向到登录页，或返回 `meta.success=false` | 抛 `NEED_LOGIN`，先尝试**静默续期**（用 `CASTGC` 换新会话） | — |
| 静默续期成功 | 无感，同步照常 | 胶囊依然是绿色「已同步」 |
| 静默续期失败 | `state.needLogin = true` | 胶囊变红 **「登录失效 · 点此处理」** |

关键点：**过期不会丢数据**。

- 已抓到的课表仍在 `web/data.json` 与浏览器 `localStorage` 里，页面**继续正常显示**（离线可看）。
- 只是不再更新；点「更新」会失败并提示原因。
- 后台每 15 分钟自动重试一次，**Cookie 一旦恢复有效会自动变绿**，不用手动刷新。

只有用户**主动退出登录**时才会清空课表数据（避免把上一个账号的课表留给下一个人看）。

### 10.2 换账号

点左上角账号名 → 面板里有三个操作：

| 操作 | 作用 |
| --- | --- |
| 粘贴 cURL → **导入并同步** | 先 `logout(wipe)` 清掉旧账号，再导入新 Cookie 并立刻同步，成功后自动换名 |
| **打开门户登录** | 新窗口打开门户，方便用另一个账号登录后去 Copy as cURL |
| **退出 / 更换账号** | 清空服务端 Cookie + 本地缓存 + 课表数据，回到「未登录」 |

面板输入框接受三种粘贴形式，`extractCookie()` 会自己识别：

```
① Copy as cURL 整段（含 -H 'cookie: ...'）   ← 推荐
② 单独的 cookie 字符串：SESSION=xxx; token=yyy
③ 只有 -b 'a=b; c=d' 的 cURL
```

### 10.3 服务端怎么知道「现在是谁」

门户**没有**可直接调用的"当前用户"接口（`users/currentUser`、`users/getUserInfo`、
`users/me` 等全部返回 `500 超出数据权限的操作` 或 `401`，加 `csrf` 头也一样，只有
`users/menus?userId=` 能通且只给菜单）。所以换账号后的身份是"拼"出来的：

| 信息 | 来源 |
| --- | --- |
| 学号 | 解码 Cookie 里 `Authorization` 那个 JWT 的 `sub`（形如 `xxxxXXXXXXXX`） |
| 班级 | 从课表教学班名里抠：`某某课程-xx xx xx班-理论` → `xx xx xx班` |
| 姓名 | 无法从接口拿到，只能用「学号→姓名」记忆表 `authMeta.known`（导入时填过就记住，退出登录不清） |

所以：**换成一个从没导入过的账号时，界面显示「学号 xxxx… · 某某班」**，功能完全正常；
同一个账号再次导入则自动恢复姓名。这也是为什么 `logout` 只清 Cookie、保留 `known` 表。

## 11. CAS 账号密码登录协议（服务端代登录）

有了 §10.2 的经验就知道「只靠粘贴 Cookie」对手机用户太难受，于是把 CAS 登录也逆向了。
全部实现见 `server/server.mjs` 的 `casCaptcha() / casLogin()`。

### 11.1 验证码

```
GET https://ids.gzist.edu.cn/lyuapServer/kaptcha?uid=
→ {"kaptchaType":"1","uid":"5b007cad…","content":"data:image/png;base64,iVBOR…"}
```

`content` 是 100×25 的 PNG，内容是一道**算术题**（如 `4 + 7 =`），答案是纯数字。
`uid` 必须和下面的 `code` 一起提交，**二者一一对应**，填错就是 `CODEFALSE`。
取验证码本身不需要任何 Cookie。

### 11.2 提交登录（关键：表单编码，不是 JSON）

```http
POST https://ids.gzist.edu.cn/lyuapServer/v1/tickets
Content-Type: application/x-www-form-urlencoded; charset=UTF-8

username=xxxxxxxxxxxx&password=<RSA 公钥加密后的密文>&service=https%3A%2F%2Fportal.gzist.edu.cn%2Fshiro-cas&loginType=&id=<kaptcha uid>&code=<答案>
```

踩过的坑：

- **必须表单编码，不能 JSON**：用 JSON 提交会得到 `500 {"meta":{"success":false,"message":"请求操作失败"}}`。
- **密码必须 RSA 加密**：登录页 JS 里有 `modulus`（`00b5eeb1…`，1024 位）和 `public_exponent=010001`
  （jsbn 分支）。实测同一账号同一密码：
  - 明文提交 → `500 系统内部错误`（服务端解密失败）
  - RSA 密文提交 → `200 {"data":{"code":"PASSERROR","data":"5,1"}}`（正常进入密码比对）
- 加密细节（**这几点错一个就登不上**，全部已在 `server/server.mjs` 的 `rsaEncrypt()` 里复刻）：

  | 项 | 正确做法 |
  | --- | --- |
  | 分块 | 每块 **126 字节**（`2×(模数的 16 位字数-1)`），不是 128 |
  | 字节序 | 每块内**小端**拼 16 位字（`word = charCode[2i] + charCode[2i+1]<<8`） |
  | 输出 | 每块 **256 位十六进制**（不足左补 0），**多块之间用空格连接** |
  | 预处理 | 口令先去空白（站点 `t.replace(/\s+/g,"")`） |

  踩坑记录：最初按「128 字节分块 + 不分空格 + 低位字在前输出」，数学上解得开但**和站点密文完全不同**，
  于是服务端解出一串乱码 → 永远返回「密码错误」。最终把站点 `app.js` 里的 jsbn 模块整块抠出来 eval，
  用它对同一口令生成密文再和自己实现逐字节比对，ASCII 口令（3/10/13/126/140 字）全部一致才算通过。
- 假账号 + 正确验证码返回 `{"data":{"code":"NOUSER"}}`，说明「验证码先校验、再查用户」。

### 11.3 返回与错误码

成功：`data.tgt`（`TGT-…`）和/或 `data.ticket`（`ST-…`）。
失败：`data.code` 为下列之一（`server/server.mjs` 里 `LOGIN_ERRORS` 已映射成中文）：

| code | 含义 |
| --- | --- |
| `CODEFALSE` | 验证码错误 |
| `NOUSER` | 用户名或密码错误 |
| `USERLOCK` / `USERDISABLED` | 账号锁定 / 停用 |
| `USERNOTONLY` | 账号不唯一 |
| `ISMODIFYPASS` | 需要先改密码 |
| `ISPHONEOREMAILORANSWER` / `ISBINDWX` / `TWOVERIFY` | 需要密保 / 绑定微信 / 二次验证（未实现） |
| `NETWORKCOMMITMENT` | 需要先签网络承诺书 |

### 11.4 换成门户会话

```
① 把 data.tgt 作为 Cookie CASTGC 存进 Cookie 罐（domain=ids.gzist.edu.cn, path=/lyuapServer）
② GET https://portal.gzist.edu.cn/shiro-cas?ticket=<ST-…>
   → 302 链上 Set-Cookie: Authorization(HttpOnly, JWT) / customsid / …  ← 这就是门户登录态
③ 兜底：直接用 CASTGC 走 §2 的静默续期（GET /shiro-cas）
```

整个登录过程在**一份干净的临时 Cookie 罐**里做：成功才替换旧账号，
失败（验证码错、密码错）则完整回滚，不会把当前还能用的账号弄掉。


### 11.5 两个坑（实测踩过）

**坑一：成功回包没有 `meta`。**
`POST /lyuapServer/v1/tickets` 成功时返回的是裸对象：

```json
{"tgt":"TGT-180205-…","ticket":"ST-180205-…"}
```

既没有 `meta.success:true`，也没有外层 `data`。如果按「`meta.success === true` 才算成功」去判断，
**登录其实是成功的，却会被误判成"未知响应"**——这正是本项目 v1 版本"密码对也登不进去"的真正原因。
正确的判定条件是：`data.code` 不存在 且 回包里能取到 `tgt`/`ticket`。

**坑二：CASTGC(TGT) 可以反复换票，不必重输密码。**
CAS 标准 REST 接口可以用 TGT 换任意多张 ST：

```
POST https://ids.gzist.edu.cn/lyuapServer/v1/tickets/<TGT-…>
     Content-Type: application/x-www-form-urlencoded
     body: service=https://portal.gzist.edu.cn/shiro-cas
  → 200，纯文本 ST-180341-…
GET  https://portal.gzist.edu.cn/shiro-cas?ticket=<ST-…>
  → 302 → Set-Cookie: Authorization / customsid   ← 新的门户登录态
```

所以服务端把 TGT 留在 Cookie 罐里（`data/auth.json`），每 5 分钟保活时顺手
「TGT → 新 ST → 门户会话」续一次：**只要 TGT 还没过期，永久免密续期**；
只有 TGT 也过期了（或换账号）才需要重新输一次学号+密码+验证码。

> 密码连续错 5 次会锁号（`data.code=PASSERROR`，`data.data` 形如 `"5,1"`＝阈值,已错次数），
> 前端会直接把"还会锁几次"提示出来。

## 12. 按周次查看（2026-10 新增）

学校的课表是**按教学周**排的（同一门课可能只在第 1–16 周有、某几周停课），
所以前端必须有「周次切换」。

### 12.1 周次参数藏在 `results` 里

`queryAWeekSchedule` 这个名字里有 Week，但它的周次参数**不叫** `week` / `weekNo` / `zc`，
而是那个看起来像「返回结果」的 `results`：

```
GET api/uppcard/kbsz/queryAWeekSchedule?cardId=<卡ID>&results=3&years=2026-2027-1
                                                ↑ 第 3 周；留空＝当前周
```

实测（同一学期，只改 `results`）：

| 请求 | `data.zs` | 非空格子数 |
|---|---|---|
| `results=`（空） | `"8"` | 24（当前周） |
| `results=1` | `"1"` | 30 |
| `results=3` | `"3"` | 34 |

`data` 里几个关键字段：

- `zs`：**这次返回的是第几周**（空参数时它会把"当前周"如实告诉你 —— 可以用来算本周）
- `weekcount`：学期总周数（本校 20）
- `xsqj` / `zsms`：星期起始、周数描述
- `resultsJsonArr`：7 天 × 12 节的字符串矩阵

> 怎么发现的：在浏览器里把门户的「我的课表」打开，看下拉框选周时新发出的请求，
> 参数列表里唯一变化的就是 `results`。

### 12.2 服务端怎么存

`server/server.mjs` 的 `doFetchAll()` 对每个学期：

1. 先请求一次「不带 results」→ 拿到 `weekcount` 和当前周 `zs`
2. 再按 `results=1…weekcount` 把**每一周都抓下来**（本校 2 学期 = 41 个请求，约 1 秒）
3. 存成 `termsData[学期].weeks = { "1": blocks[], "2": blocks[], … }`，
   同时把当前周也放一份到 `blocks` 上，兼容老前端

好处：**整学期课表都在本地**，前端换周是纯内存操作，断网也能翻；
代价是 `data.json` 从 ~10KB 长到 ~72KB（可以接受）。

### 12.3 前端交互

顶栏新增：`‹ 第N周 ▾ › 本周`

- 下拉框列 1…`weekcount`，当前周那项标注「· 本周」
- `‹` `›` 前后一周（到边界自动禁用）
- 「本周」一键回到 `currentWeek`（自己手动选过周次后就不再自动跳）
- 没排课的那一周给空态：「第 17 周没有课」
- 默认打开就是**本周**；切学期会记住你在这个学期看到第几周
